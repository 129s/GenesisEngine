# 路线图 · 侦探游戏（伦敦·世纪末）

愿景对齐：见 `docs/game-design/vision.md`；优先级与范围见 `docs/game-design/top-level-design.md`；MVP 见 `docs/game-design/mvp.md`。

里程碑（Milestones · 涌现导向）
- M0 事件与日志（1 周）
  - 事件总线/可见性/日志视图；
  - 验收：玩家在酒吧/码头可记录逐句/主题两档日志条目；地图为彩色矩形，无高亮指路。
- M1 越轨与报案（1–2 周）
  - 实现盗窃/破坏原子行为；警局前台/档案柜台的受案/提交/查询（到场办理）。
  - 验收：≥1 名 NPC 亲赴前台完成报案；玩家可旁观并留痕；自然发生 ≥1 起可调查事件。
- M2 证据板与时间线（1 周）
  - 证据板（节点/连线/冲突高亮）与时间线重建；提交“论证包”并触发简化裁决。
  - 验收：近似正确给出评级；错误结论产生现实后果与名誉变化。
- M3 媒体与显露（1–2 周）
  - 出版社/报道生成；显露窗口/节流旋钮调优；
  - 验收：报道影响警局响应与公众情绪；10–15 分钟可演示切片。

依赖与对接：
- GUI 2D 画布（证据板/时间线/日志）、对话框插槽；
- Runtime API：事件快照/Atlas 读取、JSON 载入与存档；
- 场景：彩色矩形/Portal/柜台交互点与排队；
- 音频：环境与基础 Foley。

风险与决策点：
- 涌现不足 → 提升稀缺/机会，启用显露窗口（不改事实）；
- UI 成本 → 证据板先做平面直线；
- 法理细化 → 首版止于简化裁决，完整法庭后续推进。
