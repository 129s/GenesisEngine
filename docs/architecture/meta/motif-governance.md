# 母题库治理（Motif Library Governance）· v0

目标：母题（Motif）从实例中生长，并保持尽量正交。我们用母题库的增长曲线与覆盖率结构来衡量系统的“涌现容量”，同时保留人工解释空间。

## 1. 母题的最小定义

一个母题不是一句话，而是一种“可匹配的宏观模式”，至少包含：
- **模式本体**：窗口序列/有向链（先用序列模板：A→B→C）
- **证据约束**：由 Worldline Window 的 `metrics`/`counts` 给出阈值/变化条件
- **实例链接**：能定位到“哪些窗口/哪些资源/哪些交互点/哪些 agent”作为样本

母题的“出现强度”主用 `D(w,m)`：
- `D_abs(w,m)`：覆盖窗口数
- `D_norm(w,m)=D_abs/T(w)`：覆盖占比（用于跨世界长度比较）

## 2. 候选母题从哪里来（半自动）

1) 跑大量世界，产出 worldline（JSONL）。  
2) 从窗口序列中自动提出候选：
   - 变点/阶段切分后的“章回链”
   - 分布漂移大的窗口段（JS divergence、关键指标突变）
   - 高频但解释力强的失败原因链（例如 Stockout→TargetShift→Crowding）
3) 人工命名/合并/拆分，并把候选写入母题库（暂定人工维护正交性）。

## 3. 入库前的量化检查（核心）

### 3.1 冗余/正交性（避免重复定义）
对任意两个母题 `m1,m2`：
- **共现重叠**：Jaccard（出现世界集合）与窗口级重叠率
- **互信息**：`MI(A(w,m1), A(w,m2))` 或配置条件下的 `MI(·|C)`
- **强度相关**：`corr(D_norm(w,m1), D_norm(w,m2))`（建议 Spearman）
- **条件冗余**：比较 `P(m2|m1)` 与 `P(m2|¬m1)`，避免把“链式上下游”误判为重复

判定：
- 高重叠 + 高互信息 + 高相关（跨配置都稳定）⇒ 优先合并或重写边界
- 高 `P(m2|m1)` 但低 `P(m2|¬m1)` ⇒ 更像链式依赖，可共存但要标注依赖关系

### 3.2 有效性/稳健性（避免噪声刷库）
对候选母题 `m*`：
- **显著性**：覆盖窗口的证据强度（由指标/计数构成）过线；可用 bootstrap 给出置信区间
- **seed 稳健**：同配置多 seed 下出现概率 `p` 达标（低于阈值先放“观察区”）
- **边际价值**：对现有库的覆盖提升 `Δcoverage` 或解释变点数提升达标

## 4. 评价指标（衡量涌现容量与结构性）

建议同时看三条曲线（避免只看“母题数量”被噪声误导）：
- **累积母题数**：`unique_motifs(N worlds)`（物种累积曲线）
- **新颖率**：`Δunique/Δworld`（母题库扩张速度）
- **覆盖结构**：Top-K 母题覆盖率、残差章回比例（库的解释力/可压缩性）

解释：
- “数量涨很快但覆盖低”往往是噪声或母题粒度过细；
- “数量增长慢但覆盖提高”说明系统出现稳定结构（可能更叙事化）。
