# 愿景与设计原则

GenesisEngine 旨在构建一个可扩展、可观测、可复用的“涌现式叙事模拟”核心，面向多前端（CLI/GUI/Game）共享同一运行时。

## 设计目标
- 可扩展：以数据驱动与插件化为导向，新增机制不破坏既有系统
- 可观测：内置快照/遥测/回放，问题可复现、可度量、可比较
- 可复用：模拟逻辑封装为 `genesis_runtime`，多种前端可复用
- 可测试：无头模式+端到端回归，确保行为与指标可验证

## 非目标（短期内不聚焦）
- 高保真渲染与复杂物理（优先保证模拟与可观测性）
- 大而全的内容系统（先以小而稳的机制形成闭环）

## 运行时与前端模式
- 动态库导出 C 友好 API（创建/销毁/推进/抓取快照/事件注入）
- 快照双缓冲，解决模拟线程与渲染/调试线程的数据竞争
- 前端以快照为唯一读取源：CLI/GUI/Game 共享相同数据视图

## 可观测性与质量
- 遥测指标：需求/资源/路径成本/行为选择分布
- 回放与对比：同配置多次运行可比、版本间差异可视化
- 长时回归：24 小时稳定性与指标波动阈值告警

## 性能与规模目标（阶段性）
- P0：小规模（数十代理）稳定 60Hz 步进，快照/日志不过载
- P2：中规模（数百代理）下，路径与规划具备缓存/批处理
- P4：明确热点并提供可配置降频/抽样策略
